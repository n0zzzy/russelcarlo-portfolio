The problem

Letting one AI agent "build an app" usually fails the same way: it writes everything, nobody can audit it, and it will happily deploy something that was never tested or reviewed. Real teams avoid that with roles, ownership, and sign-offs. I wanted the same discipline for agents.

The key idea: permission boundaries

Every specialist can only write to its own area. The frontend agent can touch frontend/ but is denied backend/, terraform/, and the design docs. The orchestrator can't write code at all. It only delegates, tracks state, checks gates, and routes failures back to whoever owns the fix.

That one constraint turns a chaotic agent into something that behaves like a team with clear ownership, and it makes the whole run auditable after the fact.

Gates and the human in the loop

  1. Requirements → gate: BA_STATUS: PASS
  2. Design → gate: ARCH_STATUS: PASS
  3. Build → frontend, backend, and infra in parallel
  4. Validate → QA and security in parallel, both must pass
  5. Plan → terraform plan, then the agents stop
  6. 👤 Human gate → nothing deploys until I type APPROVE DEPLOY
  7. Deploy & verify → terraform apply and live smoke tests

On any FAIL, the orchestrator sends the work back to the responsible agent and re-runs validation. A human is asked only twice: when requirements need clarification, and before deploy.

The result

From one Markdown business request, the harness designed, built, tested, reviewed, and deployed a Workshop Feedback Portal, a fully serverless AWS app:

  • One CloudFront distribution serves both the private S3 frontend and the /api/* routes, so there's no CORS and S3 stays private.
  • API Gateway → Lambda (Python) → on-demand DynamoDB, with server-side validation.
  • Least-privilege IAM: the Lambda can only PutItem and Scan one table.
  • No embedded secrets, fully disposable with terraform destroy.

Delivery: 32 resources applied (0 changed, 0 destroyed) and every live smoke test passed: frontend reachable, health OK, valid submission stored, invalid rating rejected, organizer retrieval correct.

What I took away

  • Constraints beat prompts. Permission boundaries did more for quality than any clever instruction.
  • Make every step leave a paper trail. Each agent ends with a status signal, so failures are easy to trace.
  • Put the human where the risk is. Two touchpoints, not twenty, keeps the speed without losing control.
