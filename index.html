~/how-i-work

          
I'm not the fastest coder in the room. I make the system work.

          
Honestly, I'm still growing as a programmer. My strength is the layer around the code: understanding the real-world problem, designing the architecture, and harnessing AI so it executes correctly, safely, and repeatably. I treat AI as a teammate I direct, verify, and hold accountable. That's how I get results.

    Who is it for, what does success look like, and what breaks in the real world?

  2. 02Architect before code
    Diagram the flow, the failure modes, and the cost before a single prompt.
    3. 
          
  3. 03Harness the AI
    Specs, permission boundaries, guardrails, evals, and a human gate where it matters.

  4. 04Measure & iterate

🔐 Secure
Least-privilege per agent, guardrails, PII redaction, strict security headers.
proof: per-agent permission boundaries in kiro-sdlc-agent-harness · strict CSP on this site

          
🛡️ Reliable
Retries, fallbacks, and evals that catch regressions before users do.
proof: LLM-as-a-judge evals in ai-agents-eks · automated tests gate every deploy of this site

          
🌐 Highly available
Stateless agents on managed or replicated infra, with model fallback when a provider fails.
proof: LiteLLM model plane on EKS · OpenRouter fallback pattern

          
♿ Accessible
WCAG AA contrast, full keyboard use, and respect for reduced motion.
proof: this site's Lighthouse accessibility score, checked in CI

          
📈 Scalable
Event-driven and serverless designs, autoscaling compute, parallel fan-out.
proof: EventBridge choreography · Karpenter on EKS · Step Functions fan-out

          
⚡ Efficient
The right model for each role, token budgets, and caching to keep cost sane.
proof: Haiku router + Sonnet workers in novamart
