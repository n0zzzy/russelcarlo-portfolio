~/work/linaw

An AI companion for students, where safety runs before the AI does.

Linaw ("clarity") helps college students make sense of uncomfortable group dynamics: being left on seen in the group chat, unfair workload in an org, jokes that might not be jokes. It validates feelings without accusing anyone, drafts calm replies, and lets students rehearse the hard conversation in a private sandbox.

The problem

Most students who feel excluded or pressured by classmates never talk to anyone, because they can't tell whether it's "serious enough", and they don't want to get anyone in trouble. A generic chatbot is the wrong tool here: it might store their story, repeat a real name back to a server, or confidently call someone a bully.

We built Linaw for the EdTek Con 2026 AI Hackathon, representing NU Fairview, and placed 4th.

The hard rules

Before writing any feature, we wrote the rules the AI could never break. Every feature had to fit inside them:

  • Never accuse. No guilt, no punitive reports, no retaliation. Results are a perspective, not a verdict.
  • Store nothing. State lives only in memory. No database, no localStorage, no sessionStorage.
  • Mask names before anything leaves the device. Only the masked story is ever analyzed.
  • Safety first, locally. Crisis language routes straight to the NCMH 1553 hotline, without asking a model.
  • Quick Exit everywhere. Press Esc on any screen: memory is wiped and the tab jumps to a random Wikipedia page.

Architecture

Linaw is a client-side React + TypeScript app with a hybrid engine. By default it runs fully offline with a deterministic local engine. With an API key, a Claude agent takes over the reasoning, but it only sees masked text, and any failure falls back to the local engine.

  1. Check-in → situation chips: where, who, how often, what behavior
  2. Story → typed or dictated in English, Filipino, or Taglish, masked on every keystroke
  3. 👤 Student review → the student sees the masked preview and taps to fix any missed name
  4. Local safety gate → crisis keywords end the flow here and show hotlines (zero network calls)
  5. Agent loop → the model calls local tools (classify pattern, find support, draft message), max 4 turns
  6. Output guardrails → every AI field is checked for names, blame, or retaliation; if it fails, the local text is used instead
  7. Results → clarity meter, calm and firm drafts, an anonymized counselor brief, and the Practice Arena

Guardrails I'm proud of

GuardrailWhat it prevents
scrubPIIReal names, emails, @handles, PH phone numbers, and student IDs leaving the browser. It understands Filipino markers like si, kay, and sina
runCheckSafetyA model being the one to decide whether a student is in danger
flag_safety_concernThe agent missing a crisis: it can stop the loop at any time, and it can only add caution, never remove it
verifyEvidenceThe AI putting words in the student's mouth: a quote is kept only if it appears word for word in the story
safeAgentTextBlame, names, or profanity in anything the AI writes back
local fallbackA broken experience when offline, rate-limited, or out of credits

It's the same pattern I use everywhere: the model proposes, deterministic code verifies, and a human (here, the student) checks what gets sent.

What I built

Linaw was a team build with Brandon Duran. My part:

  • The check-in gateway with a guided breathing exercise, animated mood cards, and a story clarity check.
  • The Portal Hub and its modules: rights advocate and boundary buddy, with a mascot spotlight per module.
  • Evidence highlights, the incident timeline, the action plan, and the crisis handoff in the results.
  • The EN · FIL toggle: translating the hub, triage steps, results, Practice Arena, and crisis card, plus Filipino sample scenarios.
  • Rehearsal with real messages in the Practice Arena, and the Vercel deploys.

What I took away

  • Write the "never" list first. The hard rules made every later decision faster.
  • Safety can't depend on the model being up. The crisis path works with no network at all.
  • Let the user be the last guardrail. No masker catches every name, so the student gets the final say on what is sent.
  • Language is accessibility. Many students explain feelings in Taglish, so the app had to understand Taglish too.
